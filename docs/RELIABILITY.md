# 可靠性验证与发布验收

核心补丁 1.0.1 增加可重复执行的回归；鸿蒙真机与实际 NAS 部署的结果需独立记录，不能用 CI 代替。

## 自动化验证

使用 `.node-version` 中的 Node 和 `packageManager` 中的 pnpm：

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm audit
docker build -t send-to-myself:ci .
pnpm test:recovery
```

`pnpm test` 使用临时 SQLite 和临时附件目录，不连接部署中的数据库。
`test:recovery` 创建隔离 Compose 项目、随机本机端口及临时卷目录，完成后删除测试容器和临时数据。

| 范围 | 回归内容 |
|---|---|
| 数据契约 | 元数据、幂等键、部分更新、复合/历史游标、分页大小边界 |
| 分页 | 同秒记录跨页无遗漏/重复；翻页期间插入新记录不改变旧页边界 |
| 上传 | 第二个文件 I/O 失败、数据库插入失败均回滚；同键重试成功；并发重复上传仅创建/广播一次；准备期间没有半成品时间线记录 |
| 附件 | multipart 上传/下载字节一致、中文文件名搜索、图片缩略图与损坏图片回退 |
| 回收站 | 删除后只在回收站显示，恢复后附件仍可读 |
| 认证 | 未认证拒绝、设备令牌访问、设备令牌不能签发其他令牌、吊销后拒绝访问 |
| 同步 | 两个 SSE 订阅者收到创建/更新/删除/恢复；Web 首次连接及重连都会刷新时间线 |
| 备份 | WAL 快照与 JSON 同源、外键检查、附件存在/大小/SHA-256，拒绝缺失及同大小损坏文件 |
| Docker 恢复 | 启动完整镜像，经 HTTP 上传，备份、dry-run、恢复后下载；拒绝缺附件与越界归档；空附件备份清理旧附件；保留恢复前数据 |
| 仓库启动 | 云工作区只快进更新，保留未提交文件、分叉提交、任务分支及 detached HEAD |

CI 执行类型检查、以上回归、Web/桌面前端构建、Docker 构建及恢复演练。
桌面前端构建不等于 macOS/Windows 安装包真机验收。

## 备份使用范围

脚本要求当前镜像包含 1.0.1 的备份工具，使用仓库 Compose 中的 `./data:/data` 映射。
备份短暂停服，避免快照与附件复制期间有删除/上传；脚本失败会尝试恢复服务且不公布不完整备份。
恢复先在临时目录校验，然后短暂停服替换数据目录；旧目录保留为 `data.before-restore-*`，需自行定期清理。
历史无 manifest 备份仍检查数据库、外键、附件存在与大小，不能证明文件内容未被修改。
恢复演练使用测试数据；实际 NAS 的卷权限、磁盘空间、反向代理和灾难恢复流程仍需在该部署验证。

上传在文件准备后才提交数据库，因此进程崩溃不会发布缺失附件的记录；准备阶段突然断电仍可能留下未引用的文件。
历史版本已经产生的缺附件记录不会自动修复；备份完整性校验会拒绝这些记录，需从原始文件恢复或确认后删除。

## 鸿蒙真机验收（待完成）

按 [HARMONY_SHELL.md §10](HARMONY_SHELL.md#10-验收清单) 执行，并记录核心提交/镜像版本、手机型号、系统版本、壳构建版本及结果：

- [ ] 登录成功、冷启动后令牌持久化、WebView 操作正常。
- [ ] 从浏览器分享链接、从相册分享图片；另一端无需刷新可见。
- [ ] 飞行模式分享入队，杀进程并冷启动后队列仍在。
- [ ] 联网自动补发，同一幂等键在超时重试后只有一条记录且附件完整。
- [ ] 队列补发时再次分享，确认新入队记录未被旧队列覆盖；多次网络回调不并发丢记录。
- [ ] 吊销令牌后 401 提示重新登录，待发送内容仍可找回。
- [ ] 超大小/永久错误给出可见提示及重试/删除入口，不静默丢弃待发送内容。

PWA 无系统分享接收入口及离线发送队列；桌面壳无离线发送队列。Android/iOS 客户端尚未实现。
