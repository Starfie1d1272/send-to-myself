# 鸿蒙 1.1.0：分享、待发送与后台传输

2026-11-01 开发记录。基于 PR #38 的附件修复与手机布局改动。本轮完成代码、SDK 构建和定向模拟验证，尚未操作手机、更新 NAS 或完成真机验收。

## 使用路径

- 首页页头 **⋯** → **发送文件**：可填写说明，系统文件选择器一次选取最多 20 个文件。文件异步复制到持久目录并入队后交给系统传输代理。
- 从其他应用分享文件 → **发给自己**：同样先保存，再创建后台上传任务。文本/链接沿用短 HTTP 请求与持久队列。
- 首页页头 **⋯** → **传输记录**：逐条查看正文、文件名、服务器、创建时间及进度；上传支持暂停/继续、重试和取消删除。
- 时间线图片/PDF → **分享**：原生下载到持久目录，下载完成且管理页处于前台时打开系统分享面板。切后台或离开管理页后，文件保留，可回到传输页手动分享。
- 时间线附件 → **保存**：同一后台下载流程，完成后通过系统文件选择器保存到用户选择的位置。
- 下载记录可再次分享/保存，**移除**会删除本机副本，服务器内容保留。

网页普通输入区的文件上传仍走 WebView 请求。需要后台传输时使用原生入口；本轮没有把浏览器 File/Blob 转成原生文件。

## 实现与恢复边界

### 发送队列

`QueueService.ets` 继续读取原 Preferences 队列及旧 `fileSandboxPaths`。新字段 `agentId` 对应 `request.agent` 任务；`cancelRequested` 记录尚未完成的取消操作。

- 存储锁保护读改写；逐条文件锁保护派发、确认与删除，覆盖主应用和分享扩展两个进程。
- 上传使用 `Mode.BACKGROUND`、`multipart: true`，一条消息的全部附件处于同一请求；正文和 `dedupeKey` 为字符串表单字段。
- 先创建系统任务并持久保存 ID，再调用 `start()`。在两步之间中断，重启后对 INITIALIZED 任务继续启动。
- 应用重新进入时查询系统保存的状态。COMPLETED 后确认队列完成并清理本机发送副本；失败与未知任务保留文件，等待重试。
- 失败上传重建系统任务时沿用原 `dedupeKey`；暂停任务使用原 ID 继续。服务端已有唯一键及幂等实现。
- 删除先持久化取消意图，再移除系统任务，最后移除队列及副本。取消失败时保留文件；重启继续取消。删除时若服务器已经提交，已发送消息仍在服务器。
- 正在进行短 HTTP 请求的文字项暂时不能删除；界面提示稍后重试。进度轮询不会反复重发失败文字项。

### 下载与向外分享

`NativeDownloads.ets` 持久保存下载任务及文件元数据，系统任务下载到 `filesDir/received-transfers/<uuid>/<filename>`。后台下载不直接写公共文件目录；用户保存时调用 DocumentViewPicker，复制完成文件。

- 重复点击同一服务器的同一附件复用记录。
- 完成后核对本机字节数与附件元数据，缺失或截断的文件不能分享。
- Share Kit 使用 `fileUri.getUriFromPath` 与对应 UTD；仅传文件 URI，不把完整图片/PDF 作为面板参数。
- 分享面板关闭后保留文件，接收应用可能仍需读取 URI。用户可在管理页移除本机副本。
- 已完成下载的系统任务会释放，本机记录与副本继续保留。

### 原生桥接

`NativeBridge.ets` 通过 ArkWeb `registerJavaScriptProxy` 的权限白名单约束 scheme、host、有效 port 和路径；调用时再次核对顶层页面来源及前台状态。

网页仅传附件 ID、文件名、MIME 与长度。原生构造当前服务器的 `/api/attachments/:id/raw` 地址并读取本机设备令牌。ID 不接受 URL、路径分隔符或查询串；文件名清理路径字符并限制 UTF-8 文件名长度。上传/下载关闭自动重定向，避免把认证请求转到其他地址。

网页端优先使用新桥接，旧版鸿蒙壳及普通浏览器沿用已有 Web Share/下载路径。直接网页分享需要同时更新 Web 构建与鸿蒙壳。

### 已知边界

- 传输依赖系统网络及后台调度；任务可在应用进程退出后由系统继续执行，但强行停止、设备重启、节电策略和无线网络切换均待真机验收。
- 上传使用完整 multipart 重试；当前 API 没有分片/字节续传协议。下载端也未承诺 Range 续传。本轮没有修改服务端协议。
- 服务器仍执行 `MAX_UPLOAD_BYTES`，仓库默认单文件 50 MiB；后台发送不提高限制。
- 当前允许 Wi-Fi 和计费网络，关闭漫游传输。任务可能等待系统调度或可用网络。
- 文件复制及队列持久化完成前，界面显示“准备中”；该阶段被杀进程时可能留下未入队副本。只有确认入队后的内容适用队列恢复保证。
- 进程恰在成功清除队列与清理文件之间退出时可能遗留本机副本；不会重新生成消息。下载副本由用户主动清理。
- 备份恢复后若系统任务已经不存在，会显示重试入口，保留队列文件。

## 本轮验证

- Web 构建（含 TypeScript）通过。
- 鸿蒙 `assembleHap` / `SignHap` 通过；版本 1.1.0 / 1001000，继续兼容 API 22。
- 26 项定向模拟验证通过，覆盖跨进程派发/删除、任务 ID 先持久化、失败保留、重启恢复、暂停/继续、同请求多附件、下载字节数校验及来源限制。测试使用真实非 UI ArkTS 模块，平台服务为模拟实现。
- 本轮未做真机安装、网络调度验证或系统分享接收验证。模拟结果不能证明系统面板、后台限制和目标应用 URI 读取均正常。

## 待安排的真机验收

1. 更新 Web 与壳后，分别从图片/PDF 的分享按钮进入系统面板，交给一个支持对应类型的应用；验证内容及文件名，取消后再次操作。
2. 保存文件，取消选择器后再保存，确认字节一致。切后台等待下载完成，再回到传输页分享/保存。
3. 从文件管理器多选图片/PDF 分享进应用，以及从“后台发送文件”选择大附件；验证一条消息包含全部文件且哈希一致。
4. 上传过程中切后台、断网/恢复、暂停/继续、强制停止与冷启动；检查任务状态、服务器记录数和文件字节。
5. 在启动、失败、传输中各阶段删除一条队列项，同时新增其他项；确认其他项保留，系统任务停止后才清理文件。
6. 令牌失效、文件超限、磁盘不足、系统任务不存在时，确认内容仍保留且错误可见。
7. 检查长中文文件名、大字体、输入法、返回键及深色系统下的新原生页面。
