# 架构与所有权

这是单用户 NAS 收件箱：Hono API 与 SQLite、附件目录同处核心服务，Web 使用 React Query 缓存和 SSE 失效通知，各原生壳接入同一服务。没有公共多租户服务。

| 所有者 | 职责及依赖方向 |
|---|---|
| `packages/shared` | HTTP 契约、校验与纯 URL、日期、敏感内容识别；不访问数据库或网络 |
| API items / trash | 内容不变量、持久化、去重、回收站及删除生命周期；附件存储模块负责文件准备和读取。永久删除保留最小去重回执，防止旧投递复活 |
| API preview-http / preview | 前者约束外部网络请求，后者解析并条件写回；不是任意 URL 代理 |
| Web | 操作、本机草稿、查询缓存；SSE 通知后重新查询。草稿保留不代表 NAS 已保存 |
| Harmony `ConnectionSession` | 同一连接的 origin、凭据和 revision；请求使用快照，旧结果不能清除新会话 |
| Harmony `QueueService` / `NativeDownloads` | 分别负责已交接的发送和下载文件生命周期；本机入队不是服务端确认，未知结果保留供核对和重试 |
| 发布与维护 | 构建配套核心和客户端，维护固定版本、备份和恢复说明；构建成功不等于公开发布或设备验收 |

依赖由界面与 API 指向 shared 契约；原生壳调用 API 和 Web 桥，不把凭据交给网页。持久数据库是服务端保存的确认边界，Web 草稿与原生队列是本机边界。升级前备份完整数据及原版本配置；先运行目标核心的数据库迁移，再验证旧记录、附件及客户端，回退使用升级前备份与对应旧版本。具体操作见 [DEPLOY](DEPLOY.md)，版本状态见 [RELEASES](RELEASES.md)。
